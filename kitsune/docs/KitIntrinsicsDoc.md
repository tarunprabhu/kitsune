# LLVM Intrinsic Reference

These are Kitsune-specific intrinsic functions that have been added to LLVM.
These are nearly always added by a [tapir target](glossary-tapir-target), but
may also be added by Kitsune's drivers. In most cases, these are lowered to a
call to one of Kitsune's runtime functions.

If the name of an intrinsic starts with `llvm.kit.async`, the intrinsic will
always be [non-blocking](glossary-non-blocking-intrinsic). These will always
return before the operation to be performed has completed.

## Memory Allocation Intrinsics

These intrinsics specifically allocate and free
[mobile buffers](MemoryManagement.md).


(llvm-intrinsics-mobile-alloc)=
### llvm.kit.mobile.alloc

Allocate a mobile buffer.

```llvm
ptr addrspace(67) @llvm.kit.mobile.alloc(i64 %bytes)
```

**Arguments**

```{table}
|||
|:-|:-|
| `bytes` | The size of the buffer to allocate |
```

**Returns**

: The start address of the allocated buffer. Pointers to mobile buffers are
  always in the same address space numbered 67.

**Description**

: The lowering of this intrinsic to a runtime call will depend on

    1. The tapir target that in use
    2. The uses of the buffer

  For instance, if the tapir target in use is not a GPU-centric tapir target,
  this will be lowered to simply use `malloc`. If the tapir target is either
  [cuda](tapir-targets-cuda) or [hip](tapir-targets-hip), memory will be
  allocated in Unified Virtual Memory (UVM). Both NVIDIA and AMD provide
  dedicated memory allocation functions that can be used for this. These are
  usually wrapped by the corresponding Kitsune runtime.

  Pointers to mobile buffers are always in `addrspace(67)`.


(llvm-intrinsics-mobile-free)=
### llvm.kit.mobile.free

Deallocate a mobile buffer previously allocated by
[llvm.kit.mobile.alloc](llvm-intrinsics-mobile-alloc).

```llvm
void @llvm.kit.mobile.free(ptr addrspace(67) %addr)
```

**Arguments**

```{table}
|||
|:-|:-|
| `addr` | The starting address of the mobile buffer to deallocate
```


## Common Runtime Intrinsics

These intrinsics perform most general operations that most runtimes are likely
to support.


(llvm-intrinsics-initialize)=
### llvm.kit.initialize

Initialize Kitsune's runtime.

```llvm
void @llvm.kit.initialize(i32 %tt)
```

**Arguments**

```{table}
|||
|:-|:-|
| `tt` | The tapir target whose runtime is to be initialized. |
```

**Description**

: This should generally be called as early as possible in the program. This is
  usually from tapir-target-specific initialization functions generated by
  Kitsune and registered with
  [llvm.global_ctors](https://llvm.org/docs/LangRef.html#the-llvm-global-ctors-global-variable).

  It is not an error to call this with a tapir target that does not have a
  runtime to be initialized. In such cases, when lowering the intrinsic, it will
  simply be removed.


(llvm-intrinsics-finalize)=
### llvm.kit.finalize

Finalize Kitsune's runtime. This is the opposite of
[llvm.kit.initialize](llvm-intrinsics-initialize).

```llvm
void @llvm.kit.finalize(i32 %tt)
```

**Arguments**

```{table}
|||
|:-|:-|
| `tt` | The tapir target whose runtime is to be finalized |
```

**Description**

: This should generally be called just before the program terminates. It is
  often called from a tapir-target-specific finalization function that is
  registered as a callback with the
  [atexit](https://en.cppreference.com/w/c/program/atexit) C standard library
  function.


(llvm-intrinsics-enable-verbose)=
### llvm.kit.enable.verbose

Enable verbose mode in Kitsune's runtime.

```llvm

```

**Arguments**

```{table}
|||
|:-|:-|
| `verbose` | Verbose mode is only enabled if this is non-zero |
```

**Description**

: If the runtime does not support verbose mode, this has no effect.


## Threading Runtime Intrinsics

These are intrinsics generally used by tapir targets that split
[tapir loop](glossary-tapir-loop) iterations across threads on a CPU.

(llvm-intrinsics-launch-threads)=
### llvm.launch.threads

Launch a function on one or more CPU threads. This blocks until all threads
that were launched have finished.

```llvm
void @llvm.kit.launch.threads(i32 %tt, ptr %thread_fn, i64 %idx_start,
                              i64 %idx_end, i64 %grain_size, ptr %args)
```

**Arguments**

```{table}
|||
|:-|:-|
|`tt` |  The tapir target |
|`thread_fn` | Pointer to the function to be launched on each thread |
|`idx_start` | The start index |
|`idx_end` | The end index |
|`grain_size` | The grain size |
|`args` | The argument bundle used by `thread_fn` |
```

**Returns**

: Nothing

**Description**

: This is a blocking intrinsic and returns only after all threads finish.

  This is intended to be used by CPU-centric tapir targets when lowering tapir
  loops. In such cases, `idx_start` and `idx_end` directly correspond to the
  range of the loop induction variable.


(llvm-intrinsics-async-launch-threads)=
### llvm.kit.async.launch.threads

Launch a function on one or more CPU threads.

```llvm
ptr @llvm.kit.async.launch.threads(i32 %tt, ptr %thread_fn, i64 %idx_start,
                                   i64 %idx_end, i64 %grain_size, ptr %args)
```

**Arguments**

```{table}
|||
|:-|:-|
|`tt` |  The tapir target |
|`thread_fn` | Pointer to the function to be launched on each thread |
|`idx_start` | The start index |
|`idx_end` | The end index |
|`grain_size` | The grain size |
|`args` | The argument bundle used by `thread_fn` |
```

**Returns**

: An opaque context object. This must be used to
  [join](llvm-intrinsics-sync-threads) the threads.

**Description**

: This is an asynchronous intrinsic that returns immediately after launching the
  threads. It does not wait for the threads to terminate. Callers must ensure
  that any memory modified by `thread_fn` is not accessed before
  [llvm.kit.sync.threads](llvm-intrinsics-sync-threads) is called.

  This is intended to be used by CPU-centric tapir targets when lowering tapir
  loops. In such cases, `idx_start` and `idx_end` directly correspond to the
  range of the loop induction variable.


(llvm-intrinsics-sync-threads)=
### llvm.kit.sync.threads

Block waiting for the threads launched in a previous call to
[llvm.kit.async.launch.threads](llvm-intrinsics-async-launch-threads).

```llvm
void @llvm.kit.sync.threads(i32 %tt, ptr %ctx)
```

**Arguments**

```{table}
|||
|:-|:-|
| `tt` | The tapir target |
| `ctx` | The pointer to a thread context. This will been returned by `llvm.kit.async.launch.threads` |
```

(llvm-intrinsics-async-launch-kernel)=
### llvm.kit.async.launch.kernel

Launch a kernel on a GPU. The kernel will have been generated from the body of
a tapir loop.

```llvm
ptr @llvm.kit.async.launch.threads(i32 %tt, ptr %device_code, ptr %name,
                                   i64 %trip_count, i32 %threads_per_block,
                                   ptr %kernel_props, ptr %stream,
                                   ...)
```

**Arguments**

```{table}
|||
|:-|:-|
| `tt` | The tapir target issuing this launch |
| `device_code` | Address of the global variable whose initializer contains the machine code for the kernel to be launchde |
| `name` | The name of the kernel to be launched |
| `trip_count` | The trip count of the tapir loop from which the kernel being lanched was generated |
| `threads_per_block` | The number of threads per block. If this is 0, Kitsune's runtime will determine an appropriate value to use when launching the kernel |
| `kernel_props` | The properties of the kernel being launched. These are used by Kitsune's runtime to calculate the threads per block to use when launching the kernel and, potentially, other parameters |
| `stream` | The GPU stream on which to launch the kernel. If this is `null`, Kitsune's runtime will create a new stream on which to launch the kernel |
| `...` | A variable number of arguments that are passed to the kernel when launching it |
```

**Returns**

: A (usually opaque) pointer to the stream on which the kernel was launched.
  If the `stream` argument is not `null`, it will be returned. Otherwise, the
  stream that was automatically created by Kitsune's runtime will be returned.

**Description**

: This is a non-blocking call. It will return immediately after launching the
  kernel. It is the caller's responsibility to ensure that any buffers that are
  used by the kernel are not accessed on the host until the kernel has finished
  executing. [llvm.kit.sync.stream](llvm-intrinsics-sync-stream) can be used to
  block until the kernel that was launched on this stream finishes executing.

(llvm-intrinsics-enable-refine-launches)=
### llvm.kit.enable.refine.launches

Enable launch refinement. Setting this will cause the runtime to calculate
a kernel's launch parameters based on a heuristic independent of the kernel's
properties.

```llvm
void @llvm.kit.enable.refine.launches(i32 %tt, i8 %enable)
```

**Arguments**

```{table}
|||
|:-|:-|
| `tt` | The tapir target |
| `enable` | If this is non-zero, enable launch refinement. Otherwise, the call has no effect |
```

**Description**

: In the case of NVIDIA GPU's, enabling launch refinement will cause
  Kitsune's runtime to calculate a kernel's launch parameters based an
  occupancy-based heuristic provided by CUDA's API.

  ```{warning}
  This has only been implemented in kitsune's `cuda` runtime.
  ```
