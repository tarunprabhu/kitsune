# Tapir Targets

Kitsune supports a number of tapir targets that allow parallel loops[^1] to be
compiled for both CPU and GPU. They can also be transformed to use a number of
different runtime systems. Currently only one such target may be used at a
time.

[^1]: The term "parallel loops" are used to refer both to loops where the iterations of the loop can be run independently of one another, and loops containing reductions that can be performed in parallel.

(tapir-targets-supported)=
## **Supported Tapir Targets**

The [table](#tapir-targets-table-platforms) below summarizes the tapir targets
that may be passed
as arguments to the `--tapir` command line option. The "universal" tapir targets
are guaranteed to be available and are always built. Non-universal targets
usually require dependencies that may not be available on all platforms.

(tapir-targets-cuda)=
### **cuda**

The [cuda](#cuda) tapir target lowers parallel loops to run on NVIDIA GPU's.
This tapir target is currently under active development. Currently, code for a
specific NVIDIA GPU architecture is generated when compiling with this tapir
target. Unlike other compilers, the code generated by Kitsune will not work if
run on a system containing a GPU with a different architecture. The architecture
for which to generate code is determined as follows:

1. If the `--tapir-cuda-arch=<arch>` command line option is specified, code will
   be generated for `<arch>`. `<arch>` will be of the form `sm_NNN`.

2. If `--tapir-cuda-arch=` has not been specified, and an NVIDIA GPU is present
   on the machine on which the code is being compiled, the architecture of that
   GPU will be used.

3. If an NVIDIA GPU is not present on the machine, code will be generated for
   a default architecture. The default is currently
   {{ '`{}`'.format(kitsune_cuda_arch_default) }}.

While it can lower some parallel loops, there are a number of limitations.
These are listed below:

- Only parallel loops with a depth of 1 can be lowered i.e. the bodies of
  parallel loops may not contain other parallel loops. Serial
  loops in the bodies of parallel loops are allowed and will work correctly.
  Checks for nested parallel loops are not yet implemented, so Kitsune may
  not raise an error if such loops are present in the code. Compilation may
  even succeed, but will fail at runtime.

- Any memory that is accessed within the loop must be allocated in
  [unified memory](https://developer.nvidia.com/blog/unified-memory-cuda-beginners/) (UVM). Kitsune's [memory management](MemoryManagement.md) functions should
  be used for this. In general, variables allocated on the containing function's
  stack may be used as long as their address is not taken.

- Only global variables that are compile-time constants may be used.

- Functions may be called from within a parallel loop, but those functions
  must be defined in the same translation unit as the parallel loop. There is
  some support for standard library functions. Specifically, most functions
  from [libm](https://sourceware.org/newlib/libm.html) may be used, but most
  functions from the
  [C](https://www.gnu.org/software/libc/manual/html_node/Function-Index.html)
  and [C++](https://en.cppreference.com/w/cpp/standard_library.html) standard
  libraries may not.

- Multiple GPUs are not yet supported. If more than one NVIDIA GPU is found
  on the system, only one of them will be used. Currently, there is no way to
  specify which of the GPUs should be used.

The cuda tapir target has only been tested with a limited range of GPU
architectures, most notably `sm_70`, `sm_72` and `sm_80`. Older GPU's are
unlikely to work. We attempt to test on newer GPU's when possible.

[Command-line options](KitClangOptionsDoc) most relevant to
this tapir target start with the prefix `--tapir-cuda-`. Options starting with
`--tapir-gpu-` are also recognized by this tapir target.

(tapir-targets-custom)=
### **custom**

The [custom](#custom) tapir target is a "pseudo" tapir target. The tapir target
itself is
not provided by Kitsune but is provided by the user in the form of a
dynamically loaded shared object. This shared object is passed to the Kitsune
compilers via the `--tapir-plugin=` command line option.
[This document](WritingTapirTargetPlugin.md) contains information about how
to write, build and use a tapir target plugin.

In principle, the custom tapir target could lower parallel loops to run on
CPU's, GPU's, some other hardware architecture entirely, or even on multiple
device types simultaneously.

(tapir-targets-hip)=
### **hip**

The [hip](#hip) tapir target lowers parallel loops to run on AMD GPU's.
This tapir target is currently under active development. Currently, code for a
specific AMD GPU architecture is generated when compiling with this tapir
target. Unlike other compilers, the code generated by Kitsune will not work if
run on a system containing a GPU with a different architecture. The architecture
for which to generate code is determined as follows:

1. If the `--tapir-hip-arch=<arch>` command line option is specified, code will
   be generated for `<arch>`. A list of AMD GPU architectures can be found
   [here](https://llvm.org/docs/AMDGPUUsage.html#processors).

2. If `--tapir-hip-arch=` has not been specified, and an AMD GPU is present
   on the machine on which the code is being compiled, the architecture of that
   GPU will be used.

3. If an AMD GPU is not present on the machine, code will be generated for
   a default architecture. The default is currently
   {{ '`{}`'.format(kitsune_hip_arch_default) }}.

While it can lower some parallel loops, there are a number of limitations.
These are listed below:

- Only parallel loops with a depth of 1 can be lowered i.e. the bodies of
  parallel loops may not contain other parallel loops. Serial
  loops in the bodies of parallel loops are allowed and will work correctly.
  Checks for nested parallel loops are not yet implemented, so Kitsune may
  not raise an error if such loops are present in the code. Compilation may
  even succeed, but will fail at runtime.

- Any memory that is accessed within the loop must be allocated in
  [unified memory](https://rocm.docs.amd.com/projects/HIP/en/docs-6.2.0/how-to/unified_memory.html) (UVM). Kitsune's [memory management](MemoryManagement.md)
  functions should be used for this. In general, variables allocated on the
  containing function's stack may be used as long as their address is not taken.

- Only global variables that are compile-time constants may be used.

- Functions may be called from within a parallel loop, but those functions
  must be defined in the same translation unit as the parallel loop. There is
  some support for standard library functions. Specifically, most functions
  from [libm](https://sourceware.org/newlib/libm.html) may be used, but most
  functions from the
  [C](https://www.gnu.org/software/libc/manual/html_node/Function-Index.html)
  and [C++](https://en.cppreference.com/w/cpp/standard_library.html) standard
  libraries may not.

- Multiple GPUs are not yet supported. If more than one NVIDIA GPU is found
  on the system, only one of them will be used. Currently, there is no way to
  specify which of the GPUs should be used.

The hip tapir target has only been tested with a limited range of GPU
architectures, most notably `gfx90a`, and `gfx1103`. GPUs with architectures
older than `gfx908` are unlikely to work. Newer GPU's might work but support
may lag behind support for newer NVIDIA GPU's.

[Command-line options](KitClangOptionsDoc) most relevant to
this tapir target start with the prefix `--tapir-hip-`. Options starting with
`--tapir-gpu-` are also recognized by this tapir target.

(tapir-targets-opencilk)=
### **opencilk**

The [opencilk](#opencilk) tapir target lowers parallel loops to use
[Cheetah](https://github.com/OpenCilk/cheetah), the runtime system for
[OpenCilk](https://github.com/OpenCilk/opencilk-project). This will typically
use as many Cilk workers as there are CPU cores on the system. The number of
workers can be set explicitly by setting the `CILK_NWORKERS` environment
variable. For instance, in the example below, exactly 4 Cilk workers will be
used regardless of the number of cores that are available on the system.

```
$ kitcc --tapir=opencilk -O2 -o a.out <file>
$ CILK_NWORKERS=4 ./a.out
```

If the opencilk tapir target is enabled when
[building Kitsune](GettingStarted.md#building-kitsune), a suitable version of
Cheetah will be automatically downloaded and built.

(tapir-targets-nolo)=
### **nolo**

The [nolo](#nolo) (No Lowering) tapir target is a pseudo tapir target that is
intended for Kitsune developers. This tapir target will *not* lower parallel
loops at all. As a result, tapir instructions will make their way to the code
generator often resulting in a compiler crash. This tapir target is intended to
test that the tapir instructions are correctly handled by various parts of the
compiler (except for the machine code generator which does not, and will never,
handle these instructions). It is also useful to
generate LLVM-IR containing tapir instructions from high-level source.

A [simple forall loop](#tts-simple-loop) and the post-lowering
[LLVM-IR](#tts-nolo-lowered) are shown below. Note that the `detach`,
`reattach` and `sync` instructions are present in the lowered LLVM-IR.
Contrast this with the lowered code generated by the
[serial tapir target](#tts-serial-lowered).

```
$ kitcc -O1 --tapir=nolo -S -emit-llvm -o - <file>
```

(tts-simple-loop)=
```c
#include <stdio.h>
#include <kitsune.h>

void loop(long n) {
  forall (long i = 0; i < n; ++i)
    puts("Hello\n");
}
```

(tts-nolo-lowered)=
```kitll
forall.detach:
  %i = phi i64 [ %inc, %forall.inc ], [ 0, %entry ]
  detach within %syncreg, label %forall.body, label %forall.inc

forall.body:
  %call = tail call i32 @puts(ptr @.str)
  reattach within %syncreg, label %forall.inc

forall.inc:
  %inc = add nuw nsw i64 %i, 1
  %exitcond.not = icmp eq i64 %inc, %n
  br i1 %exitcond.not, label %forall.sync, label %forall.detach, !llvm.loop !5

forall.sync:
  sync within %syncreg, label %forall.end
```

(tapir-targets-pthreads)=
### **pthreads**

The [pthreads](#pthreads) tapir target uses pthreads to run iterations of tapir
loops in
parallel on a CPU. In most cases, `N` threads are launched where `N` is the
number of visible CPU cores on the system. This may not be the same as the
number of physical cores. The number of threads to launch can be specified
manually by setting the `KIT_NUM_THREADS` environment variable when running code
compiled with `--tapir=pthreads`. For instance, the command below will only
launch 4 threads regardless of the number of available CPU cores.

```
$ kitcc --tapir=pthreads -O2 -o a.out <file>
$ KIT_NUM_THREADS=4 ./a.out
```

The current implementation simply splits the iteration space of parallel loops
evenly across all threads that are launched, but this may change in the future.

(tapir-targets-serial)=
### **serial**

The [serial](#serial) tapir target lowers parallel loops to a straightforward
serial loop.
Essentially, this discards any parallelism that the programmer has asserted is
present in the loop. This is intended to be used by Kitsune developers as a
sanity check of any transformation passes, though it could be useful for
end-users for debugging code using Kitsune's
[language extensions](LanguageExtensions.md).

The LLVM-IR produced by lowering a [simple forall loop](#tts-simple-loop)
is [shown below](#tts-serial-lowered).

```
$ kitcc -O1 --tapir=serial -S -emit-llvm -o - <file>
```

(tts-serial-lowered)=
```llvm
forall.detach:
  %i = phi i64 [ %inc, %forall.detach ], [ 0, %entry ]
  %call = tail call i32 @puts(ptr @.str)
  %inc = add nuw nsw i64 %i, 1
  %exitcond.not = icmp eq i64 %inc, %n
  br i1 %exitcond.not, label %forall.end, label %forall.detach, !llvm.loop !5
```


## **Unsupported Tapir Targets**

Kitsune's source code currently contains implementations of a number of tapir
targets that are not officially supported. These are not currently built, though
some code to support them is present. Enabling these will require changes to the
build system as well as Kitsune's source code. These are listed below for
reference. Some of these are likely to be supported in the future.

(tapir-targets-openmp)=
### **openmp**

The openmp tapir target lowers parallel loops to use OpenMP's runtime system.
This tapir target will likely be removed in favor of the [omptask](#omptask)
tapir target.

(tapir-targets-omptask)=
### **omptask**

The omptask tapir target lowers parallel loops to use kmpc task runtime calls.

(tapir-targets-lambda)=
### **lambda**

The lambda tapir target lowers parallel loops to use a generic runtime system
that operates on spawned computations as lambdas.

(tapir-targets-qthreads)=
### **qthreads**

The qthreads tapir target lowers parallel loops to use the
[qthreads](https://github.com/sandialabs/qthreads) user-level threading runtime.

(tapir-targets-realm)=
### **realm**

The realm tapir target lowers parallel loops to use
[realm](https://github.com/StanfordLegion/legion/tree/stable/realm), the
runtime used by the [Legion programming system](https://legion.stanford.edu/).
